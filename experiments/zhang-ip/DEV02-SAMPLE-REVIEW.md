# 开发集 dev-02 · 同一模型的示范性文案对照

> **重要**：以下两稿都由本轮同一助手写成，用来暴露评估维度，**不是两个独立agent生成的产出，不能当Darwin E2盲评**。不得据此报告原版/新版的胜率。作者知道两套规则，存在确认偏差。

## 测试题（摘自 test-prompts.json）
用户要求：钩子强、正文交付就业机制，不向家长派活，不以张老师自夸结尾，保持鲜明态度与可论证观点。

### 示例 A：基于一般创作建议的样稿（非独立裸跑）

**《应届生没有工作经验，就不配进好公司？》**

我真不赞成有些家长一上来就给孩子判死刑：没进过大企业，哪来的好工作？

首先，企业招聘应届生，本来就不是要求孩子带着十年履历来报到。它会看学校和专业，也会看你做过什么、能不能把事情说清楚。

举个例子，同样是投运营岗，一个孩子只写“参加过校园活动”，另一个能说明自己做过报名安排、宣传分工、现场问题处理，面试官能看到的东西就不一样。

所以家长不要光盯着孩子的学校和实习单位名字，要看他有没有实实在在做过事。

没有名企实习，不代表没有竞争力。真正重要的，是让孩子把自己的优势找到、说明白。

### 示例 B：按候选 Skill 的“机制先行”规则构造的样稿（非独立执行）

**《招聘写着“有项目经验”，到底想从孩子身上看什么？》**

我不太赞同一句话：“孩子没在大公司实习过，项目经验就等于零。”

这误会可大了。

很多家长把“项目”理解成一个响亮的单位、一张证明，或者一个听上去很厉害的活动名称。

可企业招一个活动运营人员，真正担心的不是项目名字不够大，而是现场出现问题时，这个人能不能把事情接住。

比如一场校园招聘会，孩子只是去签到、拍照，和他负责招募摊位、排场地、协调物料、处理临时撤展，是两种完全不同的经历。

后面这一种，至少可以具体讲清四件事：目标是什么，自己负责哪一环，出了什么问题，最后怎样解决。

这四件事不是套个STAR模板就算完成：如果从头到尾没有做过，问两句细节就露馅。

所以真正需要区分的，不是“校园项目”和“企业项目”哪个名字好听，而是**谁能证明自己确实处理过岗位将来还会遇到的那类问题**。

大公司经历当然可能更有价值，可单位名气替代不了个人贡献。

## 开发集对照自查（非独立盲评）

| 检查维度 | A | B |
|---|---|---|
| 明确态度 | 有，反对学历/名企经验决定论 | 有，反对把项目经验等同名头 |
| 新颖性 | 中等，与旧题“普通本科也有机会”相近 | 中等，切口更聚焦“项目经验是如何被验证的” |
| 机制具体性 | 活动分工举例，但不足以解释招聘筛选 | 区分项目类型、候选人实际负责的任务和岗位风险 |
| 给家长派活 | 结尾“找到优势、说明白”稍泛 | 主体直接展示对照细节和论证 |
| 广告/自夸 | 无 | 无 |
| 可验证风险 | 不能把抽象推断说成所有HR的统一筛选标准 | 对“企业招活动运营担心什么”属于合理机制推理，不宜冒充具体公司公开招聘条件 |
| 情绪人格 | 温和、偏劝导 | 有反对态度，但情绪仍偏理性，未达到强人物性格 |

### 本轮发现的可操作问题
- 一般化的观点文案容易以“找优势”结尾，实质上把判断任务留给观众。
- 机制具体化后，信息价值改善，但并不天然生成有穿透力的**态度与情绪**。
- 即使第二稿在若干主观指标上更好，也不能把它归因于候选 Skill：同一作者知道测试意图，也没有独立控制组。
- 这是开发阶段的写作诊断，不应提交为Darwin pair/tally的正式得票。
